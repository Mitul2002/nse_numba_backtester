# NSE Numba Backtester

A vectorized-signal / Numba-JIT-executed backtesting engine, benchmarked against a
[vectorbt](https://github.com/polakowo/vectorbt) + TA-Lib baseline across 1,014 NSE
equities.

Strategy (identical in both engines, for apples-to-apples comparison): enter when
RSI(14) crosses above 40 while EMA(10) > EMA(50); exit on an ATR(14)-based dynamic
stop-loss (2x ATR) or take-profit (3:1 reward:risk), simulated bar-by-bar.

## Why this exists

`vectorbt`'s `Portfolio.from_signals` is fast, but it's a general-purpose black box —
it doesn't cleanly expose exactly how a bar-by-bar SL/TP with position sizing and fees
resolves internally. `src/numba_engine.py` re-implements the same execution logic as an
explicit, auditable, `@njit`-compiled loop (`custom_backtest_numba_loop_atr`), so the
exact fill/fee/sizing mechanics are visible and controllable, not hidden inside a
library.

## Verified results (full universe, 1,014 NSE symbols, `evidence/`)

| | Baseline (`vectorbt` + TA-Lib) | Custom (Numba JIT) |
|---|---|---|
| Total wall time, full universe | **43.57s** | **7.06s** |
| Success rate | 1014 / 1014 (100%) | 1014 / 1014 (100%) |
| Avg time / symbol | 43.0ms | 7.0ms |

**~6.2x speedup**, single process, no parallelism — the Numba JIT compilation of the
per-bar SL/TP/position loop alone accounts for the difference (the indicator layer,
TA-Lib, is identical in both engines). Raw per-symbol timing and full metric output for
both runs are committed under `evidence/*_FULL_1014_symbols.csv` — nothing here is
recomputed or estimated, it's the literal output of the two scripts.

Run it yourself: `python src/baseline_vbt_talib.py` and `python src/numba_engine.py`,
pointed at `BT_DATA_FOLDER` (see Setup below).

## Numerical parity: what the validation actually found

`src/validate_parity.py` does an element-wise `np.isclose` comparison (rtol=1e-4,
atol=1e-6) across 25 performance metrics for every symbol. Run against the full
1,014-symbol evidence data:

- **Directionally consistent, not bit-identical.** Sharpe Ratio correlation across the
  1,014 symbols is **0.89**; win rates agree within ~4 percentage points on average.
- **Exact trade-count match: 745 / 1,014 symbols (73.5%)**, mean absolute difference
  0.3 trades/symbol.
- Metrics that compound over the full multi-year history (Total Return, Sharpe,
  Expectancy, Total Fees Paid) essentially never match at this tight tolerance — small
  per-bar differences compound over a 10-20 year daily series.
- Metrics that don't compound (Start Value, Max Drawdown Duration, trade-duration
  formatting) match ~100% of the time, as expected.

**Leading hypotheses for the divergence** (not yet root-caused to a single line):
whole-share position sizing in the custom loop (`np.floor(cash / cost_per_share)`) vs.
vectorbt's default fractional-share sizing, and the exit-priority rule when a stop-loss
and take-profit are both breached on the same bar (the custom loop always resolves
stop-loss first). Either would explain a same-strategy, different-trade-count outcome
without indicating a logic bug in either engine.

This is reported here deliberately instead of a rounded-up "95%+ parity" claim — the
validation tooling (`validate_parity.py`) is real and its output is the evidence file in
`evidence/mismatches_detailed_per_source_FULL_1014_symbols.csv`, one row per engine per
symbol per mismatched metric.

## Setup

```bash
pip install -r requirements.txt
# TA-Lib's C library must be installed separately before `pip install TA-Lib` works;
# see https://github.com/TA-Lib/ta-lib-python#installation
```

By default both scripts read from `data_sample/` (6 symbols, included, for a quick
smoke test). To reproduce the full 1,014-symbol run, point `BT_DATA_FOLDER` at a folder
of per-symbol daily OHLCV CSVs (columns: `date,open,high,low,close,volume`):

```bash
export BT_DATA_FOLDER=/path/to/your/nse_ohlcv_csvs
python src/baseline_vbt_talib.py
python src/numba_engine.py
python src/validate_parity.py
```

## Layout

```
src/
  baseline_vbt_talib.py   # reference implementation via vectorbt + TA-Lib
  numba_engine.py         # custom engine: @njit execution loop, this is the core work
  validate_parity.py      # element-wise comparison + mismatch report generator
data_sample/               # 6 symbols for a fast local smoke test
evidence/                  # committed output from the full 1,014-symbol run (not regenerated by CI)
```

## Scope notes

- Single-process, single-machine. No parallelism across symbols (numba compiles once,
  then loops sequentially through the file list) — parallelizing across symbols
  (`multiprocessing`/`joblib`) is the obvious next step and isn't implemented here.
- One strategy (RSI/EMA/ATR) is used throughout, chosen to give both engines an
  identical, non-trivial execution path (dynamic SL/TP, fees, slippage) to compare on —
  not a claim that this specific strategy is alpha-generating.
- `data_sample/` is a handful of large-cap NSE names for a quick start; the full
  1,014-symbol universe used for the verified numbers above is not included in this
  repo (~257MB of CSVs) — the `evidence/` folder is the record of that run.
